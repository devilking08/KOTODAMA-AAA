Non-technical: what is this picture?

The game is built from three layers. Content (left) is every place, person, quest and line of dialogue — plain data files. Engine (middle) is the machinery that brings the data to life: rendering, movement, combat, AI, sound, saving. UI (right) is the interface you see. Arrows show how data flows from content into the engine, and how the engine drives the UI. The loop at the bottom shows the heartbeat of the game: every frame it reads your input, updates the world, resolves the action, and draws.

Developer summary

Everything is data-driven: regions, chapters, bosses, quests, dialogue, weapons, codex, achievements, endings. The engine systems are small interpreters around one orchestrator (Game) and a typed event bus. The world is deterministic (seeded). Save state is a versioned, migrated JSON document. 41 unit tests validate content integrity and combat math.

Key invariants

1. Content never imports engine code. 2. The engine never touches the DOM; the UI is a thin surface. 3. Any region can be loaded at any chapter — chapters are just pointers into region data. 4. All combat resolves through one hit pipeline (CombatHit). 5. The save is the single source of truth; quests/achievements/endings are pure functions of it.

Plain-language transcript (screen-reader friendly) 
KOTODAMA — SYSTEM DIAGRAM transcript

CONTENT (the library on the left)
  regions.ts      six explorable worlds: the shore, the drowned bell island, the frozen
                  pass, the desert, the bamboo forest, the volcano crown. Each contains
                  landmarks (shrines, villages, ruins, arenas), people, enemy groups,
                  collectibles, secrets and spawn points.
  chapters.ts     the story route: a prologue plus ten chapters. Each chapter points at
                  a region and a spawn, names a boss, and gives rewards.
  enemies.ts      the cast: fifteen regular enemies, six elite fights, ten bosses with
                  phases, attack moves, and vocal barks.
  quests.ts      eleven main quests and twelve side quests, each staged: talk, kill,
                  collect, reach, boss, flag, or choice.
  dialogue.ts     nineteen conversation trees with choices and effects (flags, items,
                  quests, endings).
  weapons.ts      five weapons, five weapon arts, consumable items, and a skill tree.
  codex.ts       65 lore entries.
  achievements.ts 35 achievements.
  endings.ts      four endings.
  cinematics.ts   timeline cutscenes with camera, subtitles, and fades.

ENGINE (the machinery in the middle)
  Game            the conductor. It owns the save, the modes (title, playing, pause,
                  dialogue, cinematic, dead, photo, ending), and the main loop.
  Input           keyboard, mouse, and touch.
  Player          your character: movement, combat, posture, dodging, guarding.
  Enemy AI        each enemy thinks: notice, approach, telegraph, strike, recover.
  World           builds the current region from data: people, shrines, secrets, arenas.
  Terrain         the ground: heights, water, and collision.
  Weather         particles and sky effects.
  Effects         sparks, blood, sword trails, area telegraphs, projectiles, hazards.
  CameraRig       the third-person camera, lock-on, and cinematic shots.
  QuestSystem     the quest state machine.
  AudioEngine     all music and sound effects, synthesised live with Web Audio.
  SaveSystem       save slots, autosave, migration.
  Engine          the renderer, sky shader, and post-processing.
  EventBus        typed events connecting it all.
  Dialogue        reads trees, shows lines and choices, applies effects.

UI (the interface on the right)
  HUD            health, posture, gourds, resolve, flow, weapon, boss bar.
  Menus          pause, journal, map, skills, codex, settings.
  Dialogue box   speaker, text, choices.
  Overlays       chapter cards, subtitles, death screen, endings, credits.
  Photo mode     free camera and screenshot capture.
  Touch controls virtual stick, action buttons, look drag.

HOW IT FLOWS
  Content feeds the Engine: regions build worlds, chapters drive progress, quests
  and dialogue live in the QuestSystem and Dialogue systems, weapons shape the
  player, enemies populate the AI.
  The Engine drives the UI: the HUD reads player stats; menus read the save;
  the dialogue box reads the conversation; overlays react to events.
  The per-frame loop: read input → update player and enemies → resolve hits and
  effects → update camera, weather, audio → draw → repeat. Saves are written to
  the browser's localStorage on a timer and at key moments.

INVARIANTS
  1. Content never imports engine code.
  2. The engine never touches the DOM directly — the UI is a separate surface.
  3. Any region can be loaded for any chapter; chapters are just pointers.
  4. All combat goes through one hit pipeline.
  5. The save file is the single source of truth.
